## Open items for Wallie

- **Map center** — set it once per machine (`source/README.md` → "Map center"); until then the app runs without maps. Hosting needs `King__Map__Center__Latitude/Longitude` (`infra/README.md`).
- **Known gaps, not fixed in 2b** — (1) the catalog test checks message *ids*, not text, so an edited `defaultMessage` without `bun run i18n` still passes (that's how the stale tagline slipped through 2a); (2) a failed log, sighting or "Save spot" request isn't shown to the person (pre-existing for logs; spots inherit it).
- **Same-name places far from spots** — two blocks can both read "About 1,100 ft from Porch"; adding a direction ("1,100 ft north of Porch") would tell them apart. Not built; Wallie to decide.
- **`/admin` with no key hash configured** — the page still shows the key form (the SPA serves every page), but `/api/admin/check` is a 404, so checking any key says "Couldn't reach the site". Misleading only on a site without admin set up; a "not set up" message is a small fix if wanted.
- **Site size (found 2026-10-12)** — fixes 1–4 done in Slice 6 step 8b (compression + caching, Leaflet on demand, shared `@apply btn`, small avatar), and the confirmation pictures (2026-10-12, Wallie: 352 px centre squares, 194 → 45 kB and 114 → 31 kB; `LoggedScreen.test.tsx` pins them); left, Wallie's call: Latin-only font declarations (~−25 kB CSS), trimming daisyUI (−41 kB, but a later daisyUI class would silently go unstyled), stripping translator descriptions (−13 kB, needs a build plugin). Original findings: measured: the live site sends its JavaScript (481 kB) and CSS (295 kB) **uncompressed** (gzip/brotli would be ~125 kB + ~39 kB) and with no cache header on the hashed `/assets/` files. Main JS: react-dom 40%, Leaflet 29% (loaded on every visit, even without a map), the site's own code 17% (of which ~13 kB is translator descriptions), react-intl/formatjs 11%. CSS: each of 18 button classes `@apply btn` copies daisyUI's whole button (~7 kB each; one shared rule measured 295 → 168 kB), ~41 kB of unused daisyUI components, 29.5 kB of `@font-face` for every language subset (only Latin downloads). Home's `king-sitting.jpg` is 194 kB shown at 88 px. Suggested order: compression + caching (server), Leaflet on demand (−149 kB JS), shared `@apply btn` (−127 kB CSS), a small avatar image (−190 kB on Home); stripping descriptions needs a build plugin (new dependency). None started — Wallie to decide, and whether before step 9's deploy.
- **Commit author email** — `main` was pushed with `jamie@pithyplatypus.com`, so it's public in history; changing it now means rewriting history and force-pushing. For later commits only, set a noreply address (`git config user.email`) if wanted.
- **Restore into DocumentDB never rehearsed (2026-10-24 review)** — `infra/README.md` → "Restoring a backup" step 4 is `--drop` into the live database and has only run against local Mongo; the one DocumentDB difference seen so far (the index option) is exactly this layer's. Rehearse into a `king-drill` database on the cluster (`--nsFrom 'king.*' --nsTo 'king-drill.*'`), check counts, drop it; 1–2 h with Wallie present.
- **Removal on request has no path (2026-10-24 review)** — Privacy promises removal by email; nothing deletes an entry for good (`docs/patterns/admin-key.md`), so a request today means hand-written mongosh against production. A runbook with the `--config` + scrub pattern (1 h), or the "delete for good" in Later widened from photos to entries.
- **Nobody watches when the Mac doesn't deploy (2026-10-24 review)** — no `.github/`; `deploy.sh:30` uses macOS `date -v`; the .NET base image floats (`PublishContainer` sets no `ContainerBaseImage` — belongs with the first review's fix 7); the DB-IP file and the mongo digest refresh only when a human deploys.
