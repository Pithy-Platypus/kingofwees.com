# Telemetry: real failures, and the browser's errors ✅

_Moved from `PLAN.md` on 2026-10-24, as it stood._

Found 2026-10-19 (Wallie asked what the Failures blade's failures were). Every `AppRequests` row reads `ResultCode` 0 and `Success` true: the Container Apps agent doesn't map `http.response.status_code`. So the Failures blade, Smart Detection's failure anomalies and any alert on failed requests can never fire, and a run of 500s would look green. 30 days held no 5xx. The 56 "failures" were 499s (visitors leaving slow thumbnails, mostly within a minute of a new revision starting), 6,400 404s were scanners (`/wp-admin`, `/.env`), the 401s were expected. The browser sends nothing (no SDK, no error handlers, no error boundary; App Insights has no browser rows), so a render crash is a blank page with no record anywhere. Ingestion today is 1.4–8 MB a day (peak 16.7) against the 50 MB cap.

Decided (Wallie, 2026-10-19): fix the status codes; add browser diagnostics through the site's own API; sampling off (the exporter defaults to rate-limited at 5 traces a second since #54942; `SamplingRatio = 1.0f` with `TracesPerSecond = null` keeps every trace). **Approved by Wallie (2026-10-19):** (a) the route `POST /api/client-diagnostics` (routes are kebab-case: `hidden-photos`, `version`); (b) amending the server rule "public writes only in the `/api/king` writes group" to exempt an endpoint that stores nothing and only logs (the writes group's US-only filter would drop visitors abroad); (c) Live Metrics off (on by default in the Azure Monitor packages; streams outside the scrubber's tests); (d) approval to send a few local spike requests to `kingofwees-insights` under service name `kingofwees-dev` (step 1). **Decided (Wallie, 2026-10-20):** (e) only the app's own `KingOfWees` meter is exported (8 counters, at most 12 series; a View drops every other instrument when the connection string is set, so the Aspire dashboard still sees them all); 60 s interval unless unchanged series repeat every interval, then 15 minutes; **Decided (Wallie, 2026-10-20):** (f) 4xx stay failures — the data stays honest; alert only on 5xx; filter the Failures blade by response code when needed.
